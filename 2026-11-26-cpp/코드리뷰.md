## 2. 리뷰 코멘트

### C1. [L65] 조용히 넘기는 return
- 왜 문제인가: input으로 오는 값의 스키마가 잘못된 경우를 그냥 넘김. 하다못해 다른 로그로 남기거나 왜 넘어가졌는지 확인할 필요가 있음. 조용한 오류는 대부분 이런 형식에서 생김
- 언제 터지나: input으로 오는 값의 스키마가 잘못된 경우
- 대안: 따로 print나 log를 남겨야 함

### C2. [L71] 혼자서 원자성 관리가 안 되어 있음
- 왜: 다른 스레드가 해당 해시의 값을 수정할 때 동시성 문제로 실제 count 값과 다른 값이으로 수정 될 수 있음
- 언제 터지나: 같은 path에 다른 스레드가 동시에 접근하여 수정하려 할 때
- 대안: L71 std::lock_guard 밑에 해당 코드를 이동
